## Integration

The adapter connects through the existing SDK status callback flow, reads the deployed
`clip_seconds_min` / `clip_seconds_max`, disables autoplay, and enqueues a scene with
its round seed. It waits for that clip's `clip_generated`, explicitly plays it, and
requires both `clip_finished` and 120 captured frames before accepting output.

The deployed FastH3 reported a 5.167–14.375 second range. A six-second request was
accepted as 6.583 seconds. The game retains its existing five-second silent output
format. SDK 1.5.1 delivers decoded BGRA bytes on a media thread; a bounded 12-frame
buffer feeds FFmpeg. No server recording endpoint is needed. All observed frames had
zero sender timestamps, and direct frame capture completed successfully.

Prompt validation now enforces the game's 500-character scene limit and FastH3's
800-character limit for the complete rendered prompt. The Helios tokenizer is no
longer a game readiness or setup requirement. Shared session ownership, scoped tokens,
diagnostics, retry limits, 60-second lifecycle, and independent closure checks remain.
The legacy Helios spike is available through `--model helios`.

References: [FastH3 schema](https://docs.reactor.inc/model-api-reference/fast-h3/schema),
[reference implementation](https://github.com/reactor-team/infinite-livestream/tree/main/fast-h3).
