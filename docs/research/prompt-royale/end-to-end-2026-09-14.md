# Prompt Royale end-to-end verification — 14 September 2026

The host-disconnect bug and two capture/preparation bugs are corrected. Fixture games
complete through voting, scored results and replay. A real three-player Helios game was
attempted, but provider session admission/readiness failed before any frames arrived;
successful live completion is still unverified.

Final `make check` passed: 197 backend tests, Ruff, ESLint, TypeScript and the

returned `{"status":"ok"}`. The check log is `.local/prompt-royale-final-check.log`.

## Causes and changes

1. **Hidden host tab stopped its own heartbeat.** The shared polling hook skipped
   requests when `document.hidden` was true. The server correctly treated 30 seconds
   without a successful host request as a lost connection and aborted the round,
   including any running captures. Prompt Royale now opts into polling while hidden.
   The real connection-loss timeout remains, and the lobby text describes it accurately.
2. **Zero timestamps prevented recording requests.** The earlier live diagnostic
   received 735 decoded frames, all with timestamp zero, but the six-second timestamp
   gate never opened. The gate now also permits a recording request after six seconds
   of observed frame arrivals when timestamps are missing. Actual downloaded media
   duration is still validated before accepting a five-second clip.
3. **MP4 normalization lost a reliable output frame rate.** On this laptop's FFmpeg
   7.1.1, the old `setpts` pipeline re-encoded the valid five-second, 120-frame fixture
   with a reported duration of 4.958333 seconds and H.264 level 6.2. The duration check
   rejected it. Adding an explicit 24 fps filter produces 5.000000 seconds, 120 frames,
   1280×768 H.264/yuv420p at level 3.2. The duration tolerance was not relaxed.

Per-attempt diagnostics now retain connection state timings, received frame counts,
the failing stage, structured SDK error codes/HTTP status, retry delays when supplied,
and independent session closure. They exclude prompts, credentials, recording URLs
and raw provider error payloads, and survive room cleanup and process restart.

## Browser verification

All three fixture Playwright scenarios passed against the combined server on port 8000:

- Three- and four-player rounds: topic selection, refresh, coordinated arena playback,
  voting, winner/results, replay and room cleanup.
- Room code validation and join flows.
- Three isolated player contexts, including a 390-pixel phone viewport: host visibility
  overridden to hidden for 35 seconds, more than 20 successful host polls during that
  interval, three playable five-second clips, three votes, scored winner, replay and
  room cleanup. This exercises the hidden-document branch; it does not simulate an
  operating system suspending the entire browser or a disconnected physical phone.

The fixture report, with arena and results screenshots, is at
`.local/prompt-royale-e2e-fixture-report/index.html`.

The capture regression tests include missing/zero timestamps, recording errors,
privacy of diagnostics, and a mocked SDK/HTTP recording passed through the actual
FFmpeg/ffprobe preparation pipeline. Provider mocks are explicitly distinct from
successful live model generation.
